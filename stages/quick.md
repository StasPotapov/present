# Короткий путь — одна страница-презентация

Этот файл читается из `SKILL.md`, когда пользователь выбрал короткий путь: «покажи мысль картинками»,
разовая визуализация, черновик, простая презентация. Конвейера, комплекта и статуса здесь нет:
путь проходит за один заход.

Короткий путь — **другой процесс, а не дека похуже**: слайды всё так же проектируются под контент,
kernel копируется дословно, дека остаётся офлайн и самодостаточной. Экономятся шаги, а не качество.

## Что на выходе

На диске у пользователя появляется **ровно один файл**:
```
куда сказал пользователь/
└── <slug>.html            ← всё внутри: движок, стили, слайды, медиа base64
```
Черновики (текст по слайдам, промежуточные сборки) держи в scratchpad-папке сессии и **не**
складывай рядом с декой. Не создавай `deck/`, `notes.js`, `DECK.md`, `slides.md`, `design.md`
и build-скрипт: после короткого пути убирать ничего не надо.

## Окно докладчика — по умолчанию нет

- Дека короткого пути собирается **без окна докладчика**: на `<html>` стоит `data-presenter="off"`
  (kernel v7, `cookbook.md` → «Без окна докладчика»), `data-notes` у слайдов не пишутся.
- Окно делается сразу только тогда, когда пользователь прямо попросил: «с заметками», «с окном
  докладчика», «буду выступать по ней». Тогда атрибута нет, у каждого слайда — `data-notes`
  с речью из материала (свою речь не выдумывай), файла `notes.js` нет: заметки живут вшитыми.
- Поняли по материалу, что это выступление, но прямо не просили, — всё равно без окна. В финале
  предложение добавить окно прозвучит само (см. «Финал»).

## Шаги

1. **Замысел** — `stages/build.md`, Шаг 1, но хватит осей 1, 4, 5 (+9, если контент явно просит).
   Ответы всё равно свои, а не «как обычно». Арт-дирекшн держи в голове: `DECK.md` здесь нет, и
   отсылки «запиши в `DECK.md`» из ассетов на коротком пути не действуют. Текст по слайдам
   раскладываешь сам из данного материала; материала нет — не выдумывай факты и цифры, спроси
   одним вопросом или сделай слайды без них. Иллюстрация понятия (пример коммита, пример запроса)
   — не факт, её можно написать самому.
   Черновики в scratchpad не называй `slides.md`, `design.md`, `DECK.md`: валидатор по этим именам
   рядом с декой решит, что это полный путь.
   Дан `design.md` или URL-референс — он и есть арт-дирекшн (`assets/art-direction.md`).
2. **План** — без подтверждения: одна строка «собираю N слайдов, арка такая-то» и сразу сборка.
   Интерактив не обсуждается: контент явно просит — сделай один виджет и скажи о нём в финале,
   не просит — дека статична.
3. **Сборка** — `stages/build.md`, Шаг 4, пункты 1-3 и 4б, с такими отличиями:
   - вступление Шага 4 про папку `deck/` и скрипт сборки в рабочей папке не действует: файл
     собирается сразу туда, куда сказал пользователь, промежуточное — в scratchpad;
   - сразу после копии kernel поставь выключатель окна: замени `<html lang="ru">` на
     `<html lang="ru" data-presenter="off">` (если окно не просили). В kernel v7 эта строка одна;
   - пункт 3: `data-notes` у слайдов **не пишутся** (если окно не просили);
   - медиа — только inline base64. Медиа тяжелее ~800 КБ ломает однофайловость: предупреди и
     предложи ужать или перейти на полный путь;
   - пункт 5 (`notes.js`) пропускается.
4. **Проверка** — `stages/build.md`, Шаг 5: короче, но не мельче. Валидатор, `?check`, ошибки
   консоли, аудитор макета и headless-печать PDF обязательны ЦЕЛИКОМ: аудитор стоит один вызов на
   всю деку. Рационируются только кадры: титул + все слайды, которые пометил аудитор, + два-три самых
   плотных. Молча пропускать проверку нельзя. Сервер для Chrome поднимай в папке, где лежит файл,
   а не в `deck/`. Пункты Шага 5 про `DECK.md`, `deck/` и раскладку пропусти: их нет.
   Расширения claude-in-chrome нет — та же ветка, что в Шаге 5: скажи об этом в финале и попроси
   открыть деку с `?check` и пролистать глазами. Headless-печать PDF эта ветка не отменяет.

## Финал

- Отдай путь к файлу и скажи, что это вся дека целиком: переслать = переслать один файл.
- Напомни управление: `← →`/колесо/свайп — листать, `B` — чёрный экран, `F` — fullscreen,
  `S` — PDF, `?check` в адресе — подсветка переполнений. `P` упоминай, только если окно есть.
- **Последней строкой предложи окно докладчика** (если его нет): «Могу добавить окно докладчика
  с заметками — для выступления по этой деке. Сказать?». Это одна строка, не вопрос AskUserQuestion.

## Добавить окно докладчика потом

Пользователь согласился или попросил позже:
1. Сними атрибут: `<html lang="ru" data-presenter="off">` → `<html lang="ru">` (эта строка в файле одна).
2. Допиши `data-notes` каждому слайду: речь по материалу и по тексту на слайде, ремарки в `[скобках]`.
   Материала на речь не хватает — спроси, а не выдумывай.
3. Прогони проверку из шага 4 целиком. Дека остаётся одним файлом, `notes.js` не нужен.
4. Напомни про `P`: окно открывается отдельным окном, его не шарят, шарят деку.

## Доводка и раскрутка

- Доводка идёт по тому же одному файлу — `stages/build.md`, Шаг 6. Папку и комплект не заводи.
- Нужно больше — доклад, репетиции, хронометраж — это раскрутка до полного пути:
  `stages/build.md` → «Продолжить работу над готовой декой» → «раскрутка до доклада».
