## Режим деки: «скрипт»

В папке лежит `build.py` и его исходники в `src/`. **Правь исходники и пересобирай**, готовый HTML руками не трогай:

```bash
python3 build.py          # пересобрать деку в deck/ (notes.js не трогается, если он уже есть)
python3 build.py --notes   # пересобрать И перезаписать notes.js из data-notes
```

Исходники:

| файл | что это |
|---|---|
| `src/design.css` | весь беспоук-CSS деки (уезжает в `<style id="design">`) |
| `src/slides.html` | 16 секций слайдов с `data-notes` (уезжает в `#deck`) |
| `src/inter-faces.css` | 4 блока `@font-face` Inter в base64 (roman/italic × cyrillic/latin), 280 КБ |
| `src/interactive.js` | виджет слайда 09: палитры трёх дек + применение/сброс темы (уезжает в `<script id="interactive">` ПОСЛЕ kernel) |
| `src/kernel-v8.html` | копия движка из ассетов скилла — фолбэк, если скилл переехал |
| `slides-cut-15-two-circles.html` (корень) | архив: снятый слайд «два круга» целиком, с процедурой возврата в четыре шага |

Картинки в `src/slides.html` помечены маркером `IMG:имя-файла` (в двойных подчёркиваниях);
`build.py` подставляет вместо них inline data-URI из JPG в корне папки.

## Арт-дирекшн (сжато)

- **Настроение:** тёплая кремовая бумага с одним ядовито-розовым маркером (бриф Playful).
- **Палитра:** `--canvas #f6f2ee` · `--paper #fff` · `--ink #111` · `--magenta #ff2e95` ·
  `--stone #848383` · `--sand #e2dcd6`. Магента — единственный хроматический голос.
  **Вся палитра перекрываема инлайном на `<html>`** (этим живёт виджет 09), поэтому цвет в CSS пишется
  только через `var()`: акцент — числами в `--accent-rgb` (все прозрачности идут как
  `rgba(var(--accent-rgb),α)`), фон и лента — через `--bg-glow` / `--bg-warm` / `--bar-grad`,
  белый на заливках — через `--on-accent` / `--on-ink` / `--on-black`, лицо заголовков —
  через `--h-family` / `--h-style` / `--h1-w` / `--h2-w` / `--h-track`.
- **Типографика:** Inter вшит base64 (variable 100–900, прямой + курсив, cyrillic+latin).
  Заголовки — 900/700 **italic**, `line-height` 1.0–1.04, tracking −0.002em (как в брифе).
- **Фон `#bg`:** два мягких радиальных градиента (розовый отсвет справа сверху, песочный слева снизу)
  + SVG-зернистость 4.5% как «бумага». Анимирован дважды: орб дышит 34 с (моторный слой) и
  `#bg.swap` проявляет фон заново при смене палитры на 09.
- **Движение:** мягкое — `pop`/`rise` на карточках и тегах, `.chain` на 05, пульс кнопки записи на 12,
  печать на 16. Ни pipeline, ни глитча, ни scanlines — не в характере бренда.
- **MOTION LAYER v2** (в конце `src/design.css`, пришёл из Claude Design): единая партитура входа —
  лента → заголовок → лид → сноска, каскад по `nth-child` внутри рядов-схем, розовый маркер
  «дочерчивается» под акцентными словами (`h1 .mg,h2 .mg`), петли прочерчиваются сверху вниз,
  фоновый розовый орб дышит 34 с, блик по `/present <папка>`, клавиша `P` нажимается сама,
  карточка QR подмигивает, галерея 09 лежит веером (`--rot` на figure).
  Моторный слой сделан ключевыми кадрами, но `.card` и `.tab` держат `opacity:0` статикой —
  в PDF их дожимает print-хук самого kernel (`.tab,.card,.reveal,…{opacity:1!important}` внутри
  `@media print`). Следствие для проверки: гасить анимации на ЭКРАНЕ (`*{animation:none}`) без этого
  правила нельзя — карточки станут невидимыми, и кадры соврут.

## Принятые решения и отступления

- **Шрифт вшит, а не системный** (согласовано): подпись стиля — тяжёлый курсивный Inter, системный SF
  ломал бы характер. 4 subset-файла, ~280 КБ base64 внутри HTML. Дека остаётся офлайн-автономной.
- **Радиусы:** 44px у крупных карточек (как в брифе), 28px у компактных узлов схем — 44px на узле
  высотой 70px превращает его в капсулу и ломает читаемость. Это осознанное отступление.
- **Счётчиков `.count` в деке нет:** в докладе нет статистики, накручивать «0 CDN» бессмысленно.
- **Иконки — только inline SVG-штрихи в Stone**, эмодзи убраны: Do/Don't брифа прямо запрещает
  залитые цветом пиктограммы.
- **`.loopline` (петли на 03 и 11) лежит ВНУТРИ своего ряда** (`.stages` / `.cycrow`, у них
  `position:relative`, петля — `top:100%`). Если вынести её обратно на уровень `.map`/`.cyc`,
  левый конец уедет под соседние блоки и стрелка укажет не туда.
- **`.branch{align-items:flex-start}`** — при `stretch` колонка с петлёй растягивалась по высоте
  соседней карточки, и петля улетала вниз на пол-экрана.
- **Моторный слой принят из Claude Design как есть**, с одной правкой: анимация `washin` на слайде 06
  стартовала с `translateY(7%) scale(1.08)` и уводила абсолютный `::before` на 53px за нижнюю кромку —
  `?check` честно ловил переполнение на всех разрешениях. Заменено на рост от нижней кромки
  (`transform-origin:50% 100%` + `scale(1.1)` без сдвига): эффект тот же, лишней высоты нет.
  `overflow:hidden` на слайде эту проблему НЕ лечит — `scrollHeight` всё равно считает overflow-контент.
- **Ловушка анимаций:** элемент с `animation … both` (`.reveal`, каскадный `popin`) держит `transform`
  из последнего кадра ПОВЕРХ любых обычных правил — `:hover`/`[aria-pressed]` на нём не сработают, и
  порядок правил в файле не помогает. Интерактивные состояния вешать на не анимированного соседа
  (у нас — на `.deckpick`).
- Известные ловушки: `backdrop-filter` не использовать (конфликт со `slidefade`); на слайде 06
  розовый wash сделан через `.slide.wash::before` с `z-index:-1` — не менять на `filter`.
  Каскадное правило `:is(.stages,.inflows,…)>*` цепляет и `.loopline`, и `.card` внутри `.split` —
  их персональные правила обязаны идти в файле ПОСЛЕ каскадного блока, иначе перебьются.
- В kernel ничего не правилось (`WHEEL_TH`/`WHEEL_COOLDOWN` — дефолтные).

### Интерактив слайда 09 (03.09.2026)

- **Движок поднят с v5 на v6, потому что без него виджет не живёт:** в v5 клик по кнопке листает
  слайд, а пробел/Enter на ней уходят в навигацию. Слайды и design-слой перенеслись без правок —
  между версиями отличаются только guard'ы навигации и тексты справки presenter.
- **Виджет ровно один на всю деку** (ось 9: один-два интерактивных слайда, не больше). Кандидатов
  было три: 03 (подсветка ручья) отсеян — «входы равноправны» уже сказано стрелкой `merge`, нажатие
  добавило бы движение, а не понимание; 15 (демо) отсеян — там живое демо, виджет с ним конкурирует.
- **Лента каталога на 08 — не GIF, а один JPEG плюс CSS.** Четыре подряд идущих экрана
  `styles.refero.design` (y = 2330 · 3101 · 3872 · 4643, шапка сайта скрыта, при съёмке был отключён
  автоперевод Chrome — иначе Apple становится «Яблоко») склеены в ленту 1000×2159 и вшиты
  как `background-image`. Прокрутка — `@keyframes reflib-scroll` по `background-position` от `0 0`
  до `0 100%`, 38 с, `alternate`: едет вниз и обратно, стыка-прыжка нет. GIF той же длины весил бы
  мегабайты и не пережил бы печать; здесь `animation:none` в печати и в reduced-motion просто
  возвращает ленту в начало. Файл-исходник — `refero-scroll.jpg` в корне папки, 161 КБ.
- **Переодевается ВСЯ дека, а не карточка на слайде:** тезис «менялся только `design.md`» доказывается
  на живом объекте — фон, акцент, шрифт заголовков и радиусы меняются у самого экрана, на котором
  идёт доклад. Отсюда и требование к CSS: никакого хардкода цвета, всё через `var()` (см. арт-дирекшн).
- **Палитры сняты с самих скриншотов** (`PIL`, медианный срез), а не подобраны на глаз:
  acid `#8584bd`/`#f1ec63`, swiss `#222222`/`#f8f8f8`, mint `#d5f9d3`/`#f1faeb`. Отступления два:
  в acid canvas затемнён до `#7a78b5` (на оригинальном сиреневом жёлтый акцент не вытягивал контраст),
  в swiss — до `#1e1e1e` (скриншот снят с чуть засветлённого проектором кадра).
- **Тема снимается при уходе со слайда и на `beforeprint`.** Иначе случайно нажатая чужая палитра
  уехала бы в PDF и на соседние слайды. Наблюдатель — `MutationObserver` на классе слайда 09;
  сброс идёт по объединённому списку ключей всех тем, поэтому переключение acid → swiss не оставляет хвостов.
- **`--cap-on` отдельным токеном:** подпись выбранной деки по умолчанию красится акцентом, но в acid
  жёлтый мелкий текст по сиреневому не читается — там она переопределена на белый.
- **Кнопка, а не `<div onclick>`:** так работают `Tab`/`Enter`, так kernel опознаёт интерактив.
  `<figcaption>` при этом остался в `<figure>` (иначе невалидный HTML), поэтому подпись подсвечивается
  классом `.on` на `figure`, который ставит JS, — а не через `:has()`.
- **Подъём выбранного превью висит на КНОПКЕ, а не на картинке.** На `<img class="reveal">` transform
  намертво держит заполненная анимация (см. ловушку ниже), и состояние «нажато» не рисовалось бы вовсе.
- **Hover-состояния у превью нет намеренно:** ось 9 относит hover к рецидивам — на проекторе курсора
  нет, на планшете нет самого hover. Состояние показывают кольцо, подпись и строка-подсказка.
- **После клика МЫШЬЮ с кнопки снимается фокус** (`if(e.detail) b.blur()`): иначе пробел, которым
  спикер листает, уходил бы в кнопку (kernel v6 отдаёт ей пробел и Enter намеренно). При активации
  с клавиатуры (`e.detail === 0`) фокус не трогается — иначе сломался бы `Tab`-обход.
- **Клавиша `P` сбрасывает тему до того, как kernel откроет presenter.** Окно докладчика снимает
  копию документа ОДИН раз и раздаёт её обоим превью через `srcdoc`; инлайновая тема запеклась бы
  в снимок на весь доклад (внутри iframe скрипту сбрасывать уже нечего — там `current === null`).
  Перехват висит на `window` в фазе захвата, потому что kernel слушает `document`.
- **Два режима скилла вплетены в существующие слайды, без нового.** Развилка живёт на 10 («Запуск»),
  где и так объясняется, что делает команда; на 03 — только оговорка сноской, чтобы не размывать
  главную мысль якорного слайда («три файла, а не три этапа»). Плашка `1 файл` переименована в
  `1 HTML`: рядом со строкой про папку `deck/` она читалась бы как противоречие.
- **Заметки собираются парсером, а не регэкспом** (`build.py`): номера `## NN` раздаются по порядку
  секций, поэтому потерянная секция сдвинула бы речь всех последующих слайдов. Прежний регексп
  требовал строгого порядка атрибутов (`class` → `id` → `data-notes`) и молча пропускал секцию с
  любым лишним `style=`; теперь порядок не важен, а любое расхождение числа секций и заголовков —
  `sys.exit`, а не предупреждение.

## Печать в PDF — мины, снятые 03.09.2026

- `@media (max-width:900px)` был **без `screen`**, а печатный layout-viewport страницы 13.333in —
  756 CSS px, то есть мобильный брейкпоинт срабатывал в каждом PDF: слайд 09 показывал одно превью
  из трёх, 08 терял `.nav` и обрезал codecard, 07/14/16 схлопывались в колонку. Теперь
  `@media screen and (max-width:900px)`. **Новые адаптивные правила писать только под `screen`.**
- `.slide.wash::before` (розовая волна 06) начинается с `opacity:0`, а печатный сброс движка —
  `*{animation:none!important}` — псевдоэлементы не матчит, поэтому в PDF волны не было вовсе.
  Добавлен `@media print{.slide.wash::before{animation:none!important; opacity:1!important; transform:none!important}}`.
  **Любая анимация на `::before/::after` требует такой же пары правил.**
- `?check` этого не ловил и не поймает: он меряет переполнение на экране, печатную раскладку не видит.
  Проверка — только реальным экспортом (`S` или headless `--print-to-pdf`).
- **Серые прямоугольники поверх контента (жалоба 03.09.2026, вечер).** Размытые `box-shadow`
  Chrome/Skia пишет в PDF растровой маской (SMask, JPEG в градациях серого — на слайде 03 их было
  12 штук), и Quartz — движок Preview, Quick Look и вставки PDF в macOS-приложения — рисует такую
  маску НЕПРОЗРАЧНЫМ серым прямоугольником поверх соседей. Воспроизведено минимальным примером:
  из пяти карточек грязной выходит ровно та, у которой тень с blur. Лечится в kernel
  (`flattenShadows()` меняет размытые слои на хайрлайн `0 0 0 1px` того же цвета, после печати
  возвращает) — в деке править нечего, но **новые тени в `design.css` печатаются плоскими, это норма**.
- **Файл на 27 МБ.** Шум `#bg::after` (SVG `feTurbulence`, `opacity:.045`) размножался копией фона
  на каждый из 16 слайдов и растеризовался в каждую страницу. Теперь `freezeForPrint()` метит копии
  классом `.ra`/`.rb` и print-слой гасит именно растровые псевдослои: **27 МБ → 2.2 МБ**, шум при
  такой прозрачности в PDF всё равно не читался. Градиентный orb `#bg::before` остался — он вектор.
- **Проверять PDF нужно рендерером Quartz, а не poppler.** `pdftoppm` показывал ту же страницу
  идеально чистой в обоих случаях — артефакт виден только там, где его увидит зритель:
  `pdfseparate -f 3 -l 3 deck.pdf p3.pdf && qlmanage -t -s 1400 -o . p3.pdf`.

## Как править

- РЕЖИМ — «скрипт»: правь `src/*`, потом `python3 build.py`. Готовый HTML руками не трогать.
- Пришли правки из Claude Design → забирай `src/design.css` и `src/slides.html` через `DesignSync get_file`
  (сам HTML не читается — см. предупреждение вверху), клади в `src/`, пересобирай и прогоняй `?check`:
  моторные правки легко дают переполнение через transform в стартовом кадре.
- Текст/структура слайдов → `src/slides.html` (секции идут по порядку, у каждой комментарий `NN ─ заголовок`).
- Стили → только `src/design.css`; `<script id="kernel">`, `<style id="print">` и chrome-DOM (`#bar/#counter/#hint`) не трогать.
  Цвет в новых правилах — только через `var()`: хардкод не переоденется вместе с темой слайда 09.
- Виджет 09 → `src/interactive.js`. `build.py` вставляет его перед ПОСЛЕДНИМ `</body>`: первое
  вхождение лежит внутри kernel, в строке, собирающей presenter-окно. После любой правки виджет
  **прощёлкивается руками** — валидатор ловит синтаксис и порядок блоков, но не логику:
  нажать все три превью, убедиться, что дека не пролистнулась, уйти со слайда и вернуться.
- Заметки спикера → `kontekst-dizayn-golos-2026-07-28-notes.js` — **источник правды** после первой сборки:
  их правят прямо в окне докладчика («✎ править» / двойной клик, «☰ все заметки») и выгружают кнопкой
  «⤓ notes.js» рядом с декой. `data-notes` в `src/slides.html` — fallback-копия.
  **Перед `--notes` обязательно перенеси актуальный текст из `notes.js` в `data-notes`**, иначе правки с репетиции затрутся.
  03.09.2026 `notes.js` перегенерирован через `--notes` дважды (переномерация после снятого слайда,
  затем прореживание речи): оба раза перед сборкой он посекционно сверялся с `data-notes` —
  расхождений не было, ручных правок с репетиций в нём не лежало. Без перезаписи
